# Known Limitations — Professor D × AEGIS V2

Honest at spec time; remove items only when fixed and verified.

1. **No live Meta AI yet** — `META_AI_API_KEY`/`META_API_KEY`/`LLAMA_API_KEY` are NOT_SET, so Professor D runs in labeled offline-demo mode with deterministic demo responses; the adapter's live path (official Meta Model API `POST https://api.meta.ai/v1/chat/completions`, default model `muse-spark-1.3`) is verified only against mocked fetch in `tests/adapter.test.mjs` — live response quality, latency, and rate limits are unverified.
2. **Verification depth** — Re-verified this run: 52/52 Node tests pass, 0 failed, 0 skipped (`npm test` + `registry/test-report.json`), build OK (24 files), 16 negative fixtures rejected (15 in `fixtures/` + `tests/fixtures/blueprint.invalid.json`, each exit 1; world targeted rules also asserted by fixture-driven tests), blueprint valid (26 components), registry 16 verified, `node --check` clean on all JS/MJS. Still not run: browser E2E (no Chromium/Playwright in sandbox — checked via `which` + Playwright cache, never installed via `npx`/`uvx`), typecheck/lint (no tsc/eslint; zero-dep stack) — CI workflow present locally but not pushed/run on GitHub. Headless flow/world tests replay the same `src/` modules, not a real browser. Gates G2–G6 are `not-run` by design of the gate tool (blueprint-only); suite evidence lives in `registry/test-report.json`.
3. **Adaptation depth** — Diagnosis infers level/prerequisites/misconceptions from 2–4 answers; this is a heuristic estimate, not a validated psychometric model, and can misjudge prior knowledge.
4. **Simulations** — Only allowlisted tools are supported; topics needing a real simulation get a truthful "unsupported" note plus worked example/visual steps, not an interactive simulation. World demos (fractions, clouds, animals, engineering) compute their truth (equivalence, cycle stage/type, classification, design test); unfamiliar topics such as volcanoes compose a labelled diagram from primitives with `simulationSupported: false` — eruption physics is not simulated. Canvas rendering is a lightweight deterministic fallback (fractions/labels/basic shapes), not full parity with every SVG branch; very large scenes are not virtualised.
5. **No arbitrary code execution** — By design, learner/AI code is never executed outside the fixed read-only harness; some programming exercises are therefore display-and-predict rather than run-and-check.
6. **Safety filter scope** — Topic safety is a bounded check, not a guarantee; novel unsafe phrasings may need filter updates (negative tests cover known cases only).
7. **Session scope** — Student state is session-scoped unless persistence is explicitly built and tested; closing the tab may lose progress.
8. **AEGIS V2 scope** — Validator/registry cover this blueprint schema only; they are not a general-purpose build system and do not verify runtime teaching quality.
9. **No generated imagery** — No `META_IMAGE_API_KEY`/`META_IMAGE_KEY` is present and no paid generation was used (`imageGenerationHealth` reports `available: false`, `paidCallMade: false`, fallback `procedural-svg`). All visuals are procedural SVG with provenance; placeholders are labelled and never claimed as generated, and images are never used for mathematical truth. Offline directors are deterministic templates; live-AI directing is unverified without `META_AI_API_KEY`. Professor walk is a pose + CSS animation (frozen under `prefers-reduced-motion`), not skeletal animation; free-form drag is pointer-driven with a keyboard mirror for interactive objects.
