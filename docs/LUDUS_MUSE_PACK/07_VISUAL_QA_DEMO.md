# Visual & Educational QA / Judge Demo

## Why this exists
Previous Muse report admitted it built for proof not beauty, drew basic shapes, had no real image model initially, did not see final interface in browser and used passing tests as proxy. Correct this failure with mandatory **human visual gates** and browser verification.

## Stage acceptance checklist
**Character review:** Founder can identify Professor D's canonical face, vest/crest, artistic quality, poses and silhouette. Reject childish stick figure. Check anatomy, eyes, hair, clothing and outfit continuity.
**Academy review:** At 1366×768 screenshot, room fills page with beautiful original art, coherent 2.5D depth, clear teacher and learning area, no empty white canvas or cryptic labels. Responsive at mobile sizes; controls readable.
**Animation review:** At least one meaningful teaching sequence: enters, walks to object, points, allows student action, reacts accurately, changes teaching; also honors reduced motion.
**Diagnosis review:** 5–10 adaptive well-chosen questions for normal path; a different sequence for demonstrably different students; evidence and uncertainty reported. No repetitive abstract templates.
**World review:** Interactive castle construction or unfamiliar topic assembled from registered primitives and matching styled art. Direct, substantive explanation with educational cause and effect. Fractions, clouds and animals separately smoke tested.
**AI review:** Live authenticated API confirmed; lesson response not a static scripted template; report mode clearly in UI. Safe handling of credentials. API timeout failure reported with graceful fallback.
**AEGIS review:** Gates and tests report actual number, evidence and untested dimensions, not blanket 'perfect'. No unauthorized spend or publishing.

## Browser testing standard
Use browser automation if available; investigate supported browser install only with founder authorization if downloading dependencies. Regardless, get *actual visual review* by founder screenshots at specified checkpoints. Unit tests cannot evaluate visual excellence. Capture version/run date and visual defects. Avoid claiming browser test when only port health HTTP 200.

## Judge script (single reliable vertical slice)
1. Open cinematic LUDUS Academy; Professor D welcomes student with motion.
2. Judge chooses topic. Ask ~5–10 adaptive questions (consider fast demo mode with representative abbreviated screening *clearly labeled* as demo, not misrepresented as full diagnosis).
3. Professor D demonstrates with visually rich interactive objects, performs movement and explains accurately.
4. Judge interacts; Professor D notices an error and changes scene or representation.
5. End with a novel transfer challenge and honest result; optionally display AEGIS audit/evidence panel.

## Important demo discipline
A stable, beautiful, fully working vertical slice beats many nonfunctional promises. Do not falsify arbitrary topic support; if unsupported tool, present useful live teaching plus generic validated visual primitives and label limitation. Prompt founder to inspect visuals after each stage, not at the end only.
